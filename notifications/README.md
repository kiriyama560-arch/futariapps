# 無料ntfy通知の導入

## 状態と費用

本コードは未デプロイです。既存LINEのGASとは別の新規プロジェクトに配置します。カード・有料プラン・Firebase Functionsは不要。ntfy無料枠、個人GoogleアカウントのApps Script無料枠内で使い、上限に達したら停止します。

帰宅連絡は登録コードのハッシュから送信者を判定して相手にだけ送ります。画面のA/B選択だけでは通知を送れません。メモ本文を外部通知には含めません。ntfyが受け付けたこととスマホへの到着は別です。

無料ntfyのランダムなトピックはアクセス制御された非公開チャネルではありません。トピックを知る人は閲覧・投稿できるため、秘密として管理してください。提供元にも通知内容は伝わります。漏れたらトピックと登録コードを更新します。

## 管理者セットアップ（公開・認証変更の承認後）

1. `node notifications/create-device-config.cjs <リポジトリ外の非公開フォルダー>` を実行。既存ファイルは上書きしません。生成物をGitHubへ送らないでください。
2. 新しいApps Scriptプロジェクトを作成し、`Code.gs`、HTMLファイル`Bridge`、`appsscript.json`を配置。
3. 生成JSONの`scriptProperties`をスクリプトプロパティに設定。`ENABLED=false`を維持。`APP_ORIGIN`はアプリのオリジン（パスなし）。現構成はGitHub Pagesの `/futariapps/` を通知リンクに使います。
4. エディターで`installReminderTrigger_`を一度実行して認可。5分間隔のトリガーを作成。定刻の厳密な配信は保証されず、Google/端末/ネットワークによる遅延もあります。
5. 「自分として実行」「全員アクセス」でウェブアプリをデプロイ。公開URL自体は秘密ではなく、各操作は登録コードで認証します。登録コードやトピックをURLパラメーターに含めません。
6. 各スマホのアプリ設定→通知設定でデプロイURLとその端末の登録コードを入力。AはAndroid側、BはiPhone側として準備し、アプリの利用者設定も一致させます。
7. 両方のスマホにntfyをインストールし通知を許可。サーバーは `https://ntfy.sh`、トピックは画面に表示された自分用の値を登録。相手のトピックを登録しないでください。
8. `ENABLED=true`へ変更後、明示承認したテストとしてA→B、B→A、メモの未来時刻予約・編集・取消を実機で確認。届かない場合は有効化完了と扱わないでください。

## 仕様・制限

- 予約可能期間は未来の366日以内、最大100件。5分間隔で確認し1回に最大10件を処理。
- 帰宅連絡は1分に1回。全体で1日100送信試行まで。サービス側上限が低い場合はそちらが優先。
- 失敗した予約は15分後に再試行。合計8試行または1日経過で破棄。管理画面の配送ステータスは未実装のため、フロントの「予約済み」は配信済みを意味しません。
- 成功した宛先を記録して通常の二重送信を抑制。送信成功直後のサーバー停止や通信切断では重複する可能性があり、厳密なexactly-once保証はありません。
- 端末登録コードはそのブラウザーのlocalStorageへ保存。端末共有・同一オリジンのスクリプトによる漏えいに注意。現アプリのFirestoreアクセスルール/本人認証は別途確認が必要であり、本変更で既存データ全体のアクセス制御を改善したとは扱いません。
- 旧版アプリからのメモ変更は通知予約と連動しないため、公開後は2人ともページを再読み込みしてください。

## テスト

`node --test notifications/test.cjs`

外部送信なしで本人判定、相手限定、再送制限、未来時刻、編集・取消、失敗時の再試行を検証。GAS実行・ntfy実配信・端末受信の確認とは別です。
